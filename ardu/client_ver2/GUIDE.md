# 아두이노 노드 만들기 — 설명서

이 폴더(`ardu/`)가 **한 벌**이다. 스케치에는 *"모르면 바로 틀리는 것"* 만 남기고,
**"왜 그런가"는 여기 있다.**

---

## 0. 시작하기 — 🔴 **프로젝트 이름을 `client` 로 만들어라**

```
① Arduino IDE 에서 **새 스케치 → 이름을 `client`** 로 저장한다
② `파일 > 스케치 폴더 열기` → 🔓 **이 폴더의 `.ino` 와 `.h` 를 전부 복사**
   (`client.ino` 는 자동 생성된 것을 **덮어쓴다**)
③ 🔴 **`Config.h` 를 열어 SSID · 비밀번호 · 서버 IP 를, `client.ino` 머리에서 `DEVICE_ID` 를 바꾼다**
④ 보드 `Arduino Uno` · 포트 선택 → 업로드
```

### 🔴 왜 이름이 `client` 여야 하나 — 다른 이름이면 **첫 시도에서 막힌다**

Arduino IDE 는 **폴더 이름과 같은 `.ino`** 를 메인으로 삼고, **폴더 안의 `.ino` 를 전부 이어 붙인다.**
그래서 프로젝트를 `MyParking` 으로 만들고 `client.ino` 를 복사하면 **`.ino` 가 둘**이 되고:

```
client.ino:1:6: error: redefinition of 'void setup()'
client.ino:2:6: error: redefinition of 'void loop()'
```
**실측한 값이다.** 이름을 `client` 로 하면 자동 생성된 `client.ino` 를 그냥 덮어써서 끝난다.

⚠ 다른 이름을 쓰려면 자동 생성 `.ino` 를 지우고 `client.ino` 를 폴더 이름에 맞춰 바꿔야 하는데,
**그러면 `client.ino` 라는 이름이 사라져 이 문서와 주석의 참조가 전부 어긋난다.**

### ⚠ 탭이 20개 넘게 열린다 — 정상이다

IDE 는 폴더의 `.h` 를 전부 탭으로 연다. 🔑 **그중 네가 여는 것은 둘뿐이다:**
```
`client.ino`  — 모듈 표 · 명령 핸들러 · setup/loop
`Config.h`    — SSID · 비밀번호 · 서버 IP · 포트
```
나머지는 링크 계층과 프레임 처리다. **§5 를 읽기 전에는 안 열어도 된다.**

### `setup()` / `loop()` 는 두 줄이면 끝난다

```c
void setup() {
  Serial.begin(115200);
  node.begin();                          // 링크 시작 · 슬롯 원점 · 난수 시드 · 리셋선

  pinMode(2, INPUT_PULLUP);              // 🔓 내 핀 — 아두이노 기본 설정
  pinMode(13, OUTPUT);

  node.sensor  ("A1").on(readA1);        // 🔓 이름 ↔ 함수
  node.actuator("LD").on(cmdLed);
  node.actuator("L2").on(cmdL2);
}

void loop() {
  node.tick();                           // 한 박자: 수신 → 센서 훑기 → 송신 → 계수
}
```
🔑 **한 줄에 모듈 하나.** 배열도 등록표도 없다. **모양이 늘 같다** — 이름 하나, 함수 하나.
🔴 **핀은 장치가 모른다.** `pinMode` 로 잡고 함수 안에서 `digitalRead(9)` 로 읽는다 —
아두이노에서 늘 하던 그대로다. 그래서 핀이 하나든 둘이든(초음파 trig/echo) 등록이 안 바뀐다.
⚠ **적은 순서가 전선 순서다**(`idx`·`occ` 비트). 센서·액추에이터를 **섞어 적어도 된다** —
순서 규칙은 없다. 다만 **중간에 끼우면 뒤의 `idx` 가 밀려** 지금 되는 결속이 조용히 깨진다.
🔑 **`begin()`·`tick()` 안의 순서는 네가 바꿀 수 없어서 감춰 뒀다**(정의는 `Runtime.h`).
드러내 봐야 *지킬 의무* 만 생기고 얻는 것이 없다. **이 두 함수에는 바꿀 수 있는 것만 남아 있다.**

⚠ **`node.tick()` 을 빼거나 `delay()` 로 막지 마라.** 한 박자가 1.2초 슬롯을 지키는 구조라
막으면 그 슬롯을 놓친다. 오래 걸리는 일은 센서 함수 안에서 **간격을 두고 캐시**해라(§4).

## 1. `DEVICE_ID` — 안 바꾸면 어떻게 되나

규격은 **1~8자**(영문자·숫자·`_`·`-`). 길이는 `static_assert` 가 막는다.

🔴 **안 바꿔도 로컬에서는 아무 문제가 없다.** 충돌할 상대가 없기 때문이다.
**여러 사람의 노드를 한 서버에 모으는 순간** 같은 이름끼리 서로를 쫓아낸다 —
서버는 `devid` 로 노드를 가르고 **같은 이름이 오면 앞의 것을 대체**한다.

⚠ 증상이 *"내 자리가 가끔 사라진다"* 로 나타나 **원인을 찾기 매우 어렵다.**
각자 로컬에서는 잘 되던 것이라 **아무도 자기를 의심하지 않는다.**

> ### **결함이 *생기는* 단계와 *드러나는* 단계가 멀다. 그 사이가 통째로 낭비다.**

값을 바꾸면 **다시 구워야 한다**(컴파일 상수).

## 2. 모듈 등록 — `sensor` 와 `actuator` 둘

```c
node.sensor  ("A1").on(readA1);             // 값을 **읽는** 함수를 붙인다
node.actuator("LD").on(cmdLed);             // 명령을 **받는** 함수를 붙인다
```

### 🔑 배우는 것은 **둘**이다

```
sensor   … 값을 **읽는다**.  함수 모양 `bool 이름()`          — true = 찼다
actuator … 값을 **쓴다**.    함수 모양 `bool 이름(uint32_t)`  — true = 성공
```
🔴 **둘 다 `.on()` 이 필수다.** 안 붙이면 센서는 늘 0(비었다)이고 액추에이터는 `result=3` 이다.
부팅의 `[SENS]` 줄이 **`🔴함수없음`** 으로 그것을 지목한다.
⚠ 옛 판에는 종류가 다섯(`IP`·`IX`·`OG`·`OL`·`OB`)이었고 **기여자가 그 글자를 외웠다.**
🔑 서버·화면은 **첫 글자만** 동작에 쓴다(`kind[0]=='O'` = 명령을 받는다). 둘째 글자는
**화면 라벨의 폴백**일 뿐이고 **정본은 서버 조립 표**다: `lot.label("P1","LD","안내등")`.
**그래서 장치가 그것을 다섯으로 말할 이유가 없다.** 지금 전선에는 `IP`/`OG` 만 나간다.

### 이름은 정확히 2글자다 — **컴파일이 막는다**

```c
node.sensor("ABC")   →  error: invalid initialization of reference of type 'const char (&)[3]'
```
🔑 주석이 아니라 **타입이 강제한다.** 그 줄을 짚어 준다.
⚠ 서버 조립 표(`lot.cpp`)의 이름과 **글자 그대로** 같아야 붙는다. 갈리면
등록은 성공하고 **자리에는 아무것도 안 붙는다. 오류도 안 뜬다.**

### 모듈을 늘릴 때

**`setup()` 에 한 줄을 더한다. 그것이 전부다.**
그리고 **서버 조립 표에도 한 줄**을 더해야 한다 — 안 하면 `미결속모듈` 로 뜬다.
```
🔴 상한은 **8개**다. 넘기면 부팅에서 `[CFG] 🔴 모듈 상한 …` 이 나오고 초과분은 버려진다
   ⚠ 조용히 버리지 않는다 — 그 줄이 없으면 "내 모듈이 왜 안 뜨지" 를 서버에서 찾게 된다
   실측 근거 : 모듈당 RAM 약 9B · `ramLow` 537B 대비 8개가 안전한 선이다
🔑 순서 규칙은 **없다.** 센서를 앞에 모을 필요가 없다 — `occ` 비트는 모듈 인덱스이고
   센서는 값으로, 액추에이터는 에코로 자기 비트를 세우므로 겹치지 않는다
```

## 3. 명령 받기 — `node.actuator(...).on(...)`

```c
bool 이름(uint32_t arg);      // true = 성공(ACK result=0) · false = 수행 불가(3)
node.actuator("모듈이름").on(핸들러);   // setup() 에서
```

### 🔴 `arg` 의 뜻은 **네가** 정한다

**서버도 프로토콜도 `arg` 의 뜻을 모른다.** 32비트 정수를 실어 나르기만 한다.
그 표를 **서버 쪽 사람과 맞춰야 하고, 양쪽에 같이 적어야 한다:**

```
여기(장치 콜백)  ─── 같은 표 ───  서버 호출부(srv.send)
```

⚠ **표가 어긋나면 조용히 다른 동작을 한다.** 오류도 안 뜬다 —
서버는 `2` 를 보냈고 장치는 `2` 를 받았으니 **양쪽 다 성공이다.**
> ### **의미는 값으로 검증되지 않는다. 사람이 맞추는 수밖에 없다.**

❌ 표 없이 `1,2,3,4` 만 쓰지 마라. 반년 뒤에 아무도 못 읽는다.

### 세 가지 꼴

```c
① on/off    digitalWrite(PIN, arg ? HIGH : LOW); return true;
② 숫자 전달  if (arg > 9999999UL) return false;  lcdPrint(arg);  return true;
③ 동작 명령  switch (arg) { case 1: … default: return false; }
```

### 🔴 거절할 때도 한 줄 남겨라

`false` 를 내는 자리마다 로그를 하나 둔다. 안 두면 **"거절했다"와 "안 불렸다"가
장치 쪽에서 같은 모양**이 된다 — 둘 다 아무 줄도 안 나오기 때문이다.

⚠ 그리고 그것이 **가장 먼저 겪는 실패**다: 값을 보냈는데 `result=3` 이 왔고 시리얼은 비어 있다.
*"내 콜백이 안 불린 건가, 불렸는데 거절한 건가?"* — 답이 없다.

**판별자**: *"내 콜백이 `false` 를 낼 수 있는 모든 자리에 로그가 있는가."*

라우터도 거들어 준다 — 사유를 셋으로 갈라 찍는다:
```
[G] 거절 idx=n — 인자 해독 실패   → 프레임·서버 쪽
[G] 거절 idx=n — 등록 없음        → setup() 의 `.on(...)` 이 빠졌다
[G] 거절 idx=n — 콜백이 거절 arg=v → 네 핸들러
```
🔑 **고치는 곳이 다 다르다.** 그래서 갈라 놓았다.

### 에코 — 서버는 무엇으로 "먹었다"를 아나

명령이 성공하면 그 모듈의 비트가 `S` 프레임의 자리 비트열에 실려 나간다(전선 비용 0).
기본값은 **`arg != 0` 이면 켜짐**이다.

🔴 **동작 명령에는 그 기본값이 안 맞는다.** 명령표가 `1=열기 2=닫기` 라면
**닫기(2)도 0 이 아니라서** 에코가 켜진 채 남는다 — 문은 닫혔는데 서버는 열린 줄 안다.
→ `router.echoIs(arg == 1);` 을 핸들러 안에서 불러 직접 정한다.

**판별자**: *"명령표에 **끄는 값이 0 말고 따로 있으면** 반드시 불러라."*

⚠ **한계 둘을 알고 써라:**
- 비트는 숫자를 못 나른다. 표시기에 `1234567` 을 보내도 에코는 **"0이 아니다"** 만 말한다.
- 🔴 **`에코 == 요청` 은 "장치가 그 값을 갖고 있다"이지 "명령이 상태를 바꿨다"가 아니다.**
  차단봉이 걸려 있어도 콜백은 `true` 를 내고 비트도 선다.
  **물리 확인이 필요하면 리밋 스위치를 `I*` 모듈로 한 줄 더 붙여라** — 그건 센서다.

### 묶음 하행

서버는 한 번에 **4건**까지 묶어 보낸다. 그래서 샘플의 명령 모듈이 넷이다.
⚠ 묶음은 **수신 창(슬롯 뒷 600ms)** 안에 와야 한다 — 장치가 송신 중이면
**첫 줄만 남고 나머지가 버려진다**(`penddrop` 이 그때 오른다).
🔑 묶음은 손실 *확률* 을 안 바꾸고 손실 *크기* 를 N배로 만든다.

## 4. 센서 읽기 — `node.sensor(...).on(...)`

> 🔑 **`client.ino` 에 두 꼴이 이미 켜져 있다** — 베낄 것을 여기서 찾지 말고 그 파일을 봐라.
> `A1` = 초음파(HC-SR04 · Trig 2 · Echo 4) · `B1` = 접점(9번 핀). **둘 다 `.on(내함수)` 한 줄이다.**

```c
bool 이름();                  // true = 찼다
node.sensor("모듈이름").on(핸들러);     // setup() 에서
```

🔴 **안 붙이면 그 센서는 늘 0(비었다)이다.** 화면에는 "빈 자리"로 보여서 조용하다 —
부팅의 `[SENS]` 줄이 **`🔴함수없음`** 으로 지목하니 그것을 봐라.

리드 스위치·적외선처럼 켜짐/꺼짐만 내는 센서도 **한 줄이면 끝난다**:
```c
bool readB1() { return digitalRead(9) == LOW; }
```

### 🔴 문턱 판정은 핸들러가 한다

초음파는 **거리(숫자)** 를 내는데 자리 상태는 참/거짓이다.
*"몇 cm 아래면 찼다고 볼 것인가"* 는 **장치를 단 사람만 안다.**
비워 두면 그 판정이 서버나 화면으로 새어 나가 **규칙이 두 곳에 생긴다.**

### ⚠ 이 함수는 매 `loop()` 마다 불린다

오래 걸리는 측정을 그대로 넣으면 슬롯이 밀린다.
- `pulseIn` 은 **타임아웃만큼 블로킹**한다. **타임아웃을 안 주면 기본값이 1초다** —
  반향이 없을 때 장치가 1초 멈춘다.
- 🔴 **타임아웃은 문턱에서 유도해라.** 문턱보다 먼 것은 어차피 "비었다"이므로 더 기다릴 이유가 없다:
  ```c
  #define US_TIMEOUT_US ((unsigned long)US_NEAR_CM * 58UL * 2UL)   // 60cm → 6,960µs
  ```
  ⚠ **4m(25,000µs)로 두면 비싸다.** 200ms 간격이면 슬롯(1,200ms)당 6회이므로
  무응답일 때 **150ms = 슬롯의 12%** 를 버린다. 문턱에서 유도하면 **42ms = 3.5%** 다.
- `LiquidCrystal` 류는 `delayMicroseconds` 로 블로킹하고, I2C 판은 버스가 죽어 있으면
  **타임아웃까지 멈춘다.** 붙일 거면 **값만 저장하고 실제 출력은 송신 창에서** 해라.
- 🔑 **간격을 두고 값을 캐시해라.** 200ms 면 차가 들어오는 속도에 충분하다.

### ⚠ 거리가 실제보다 **멀게** 나올 때가 있다 — 센서 탓이 아니다

`pulseIn` 은 **인터럽트를 끄지 않는다**(AVR 코어 `wiring_pulse.c` 확인). 그래서
`SoftwareSerial` 이 하행 바이트를 받는 순간 그 인터럽트가 계수 루프에 끼어들어
**측정값이 늘어난다** = 거리가 멀게 나온다 = 점유를 **놓친다**.

```
방향이 한쪽이다 : 값은 늘어나기만 한다. 짧아지지는 않는다
빈도            : 하행이 오는 순간에만. 평상시엔 정확하다
바이트 유실     : 없다 — 인터럽트가 살아 있으므로 수신은 계속된다
```
🔑 **문턱을 실측으로 정할 때 "하행이 오는 중"에도 한 번 재 봐라.** 여유가 없으면 그때만 튄다.

### 🔴 센서 함수는 **즉시 반환해야 한다** — 예산이 66ms 다

블로킹하는 동안 `espRead()` 가 안 돌고, 그 사이 도착한 하행이 링버퍼(64B)에 쌓인다.

```
🔴 버퍼 예산  : 960 B/s × T ≤ 64B  →  **T ≤ 66ms**   ← 이것이 결정한다
   송신 창 예산 : 읽기 합 + 185ms ≤ 400ms  →  합 ≤ 215ms
```
**둘 중 작은 쪽이 답이다. 66ms 다.** ⚠ 두 수를 섞지 마라 — 아래 표가 그것을 갈라 놨다.

| 센서 | 한 번 블로킹 | 66ms 예산 |
|---|---|---|
| **적외선(IR) 디지털** | **~4 µs** | ✅ 사실상 공짜 — 8개 = 32µs = 예산의 0.05% |
| 적외선(IR) 아날로그 | ~104 µs | ✅ 공짜 |
| 리드 스위치·홀·매트 | ~4 µs | ✅ 공짜 |
| `analogRead` | ~100 µs | ✅ 공짜 |
| I2C 한 바이트 | ~1 ms | ✅ |
| HC-SR04 초음파 | **6.96 ms** (문턱 60cm) | ✅ 8개까지 |
| DHT11 / DHT22 | ~20 ms | ⚠ 3개까지 |
| 🔴 DS18B20 온도 | **~750 ms** | 🔴 **하나도 안 된다** |

### 🔑 오래 걸리는 센서는 **두 박자로 나눈다** — 프레임워크는 안 바뀐다

측정을 *시작하고 지난 값을 돌려준 뒤*, 다음 박자에 결과를 읽는다:

```c
bool readTemp() {
  static bool waiting = false;  static unsigned long t0;  static bool last = false;
  if (!waiting) { requestTemperature(); t0 = millis(); waiting = true; return last; }
  if (millis() - t0 < 750) return last;                 // 🔑 즉시 반환한다
  last = (readTemperature() > 25.0); waiting = false; return last;
}
```
**아두이노에서 이미 흔한 패턴이다.** 초음파 예시의 200ms 캐시가 같은 모양의 작은 판이다.

### 🔴 초음파를 여러 개 달면 — **축이 셋이다. 섞어 읽지 마라**

게이트(200ms)는 센서마다 따로 만료되므로 총량이 곱해진다.
그리고 **부팅 직후에는 전부 한꺼번에** 막힌다.

| 초음파 | ① 한 번에 **연속** | ② 슬롯당 **누적** | ③ 결과 |
|---|---|---|---|
| 1개 | 6.96 ms → 6.7 B | 41 ms (3.4 %) | ✅ |
| 3개 | 20.9 ms → 20.0 B | 125 ms (10.4 %) | ✅ |
| 8개 | **55.7 ms → 53.5 B** | 334 ms (27.8 %) | ⚠ 여유 11 B |
| 10개 | 69.6 ms → **66.8 B** | 418 ms (34.8 %) | 🔴 **버퍼가 넘친다** |

```
① **연속** 블로킹 → 🔴 **버퍼 넘침** 축. 위 66ms 예산이 이 열을 본다
② **누적** 블로킹 → 루프 지연 축. 버퍼와 무관하다
🔑 ①과 ②를 나란히 놓고 ②로 버퍼를 계산하면 틀린다. **다른 축이다**
```

### 🔑 그런데 **이 표가 걱정거리인 센서는 초음파뿐이다**

```
초음파       6.96 ms   ← 🔴 유일하게 예산을 먹는다
IR·리드·홀   ~4 µs     → **1,700배 빠르다.** 8개 달아도 32µs = 예산의 0.05%
```
**그래서 자리마다 초음파를 쓸 이유가 없다.** 거리가 필요 없는 자리(있다/없다만 아는 자리)는
**IR·리드 스위치가 더 낫다** — 빠르고, `pulseIn` 인터럽트 왜곡(§위)도 없고, 코드가 한 줄이다.
🔑 **초음파는 "얼마나 가까운가"를 알아야 할 때만 쓴다.**

### ③ 세 번째 축 — **송신 기회 상실** (침범이 아니다)

```
송신은 슬롯의 **0~400ms** 안에서만 시작한다(`slotUsed + 200 <= 600`).
초음파가 그 경계를 밀면 → 🔴 **아예 안 보낸다.** 수신 창을 침범하지는 않는다
→ 대신 `[CNT]` 의 **`smiss`** 가 오른다. **그것이 이 축의 계측기다**
```
🔑 **가드가 있어서 "침범"이 아니라 "기회 상실"이다.** 하행을 잃는 대신 상행을 한 박자 늦춘다 —
**설계가 그쪽을 고른 것이다**(하행 유실은 되돌릴 수 없고, 상행 지연은 다음 슬롯에 만회된다).

### ⚠ 그리고 **송신 중 유실은 성질이 다르다** — 초음파와 섞지 마라

```
초음파 블로킹  : 인터럽트가 **살아 있다** → 버퍼에 쌓인다 → 넘치면 잃는다
🔴 송신 185ms  : `SoftwareSerial` 이 `cli()` 로 인터럽트를 **끈다**
                → 그동안 오는 것은 **통째로 유실.** 버퍼에도 안 남는다
```
🔑 **수신 창(600~1200ms)을 비워 둔 이유가 뒤쪽이다.** 앞쪽은 용량 문제이고 뒤쪽은 원리적 유실이다.

### 핀 모드 — 🔓 **네 일이다**

```c
void setup() {
  node.begin();
  pinMode(9, INPUT_PULLUP);              // 내 센서
  node.sensor("B1").on(readB1);
}
bool readB1() { return digitalRead(9) == LOW; }   // 극성도 여기서 정한다
```
🔴 **장치는 어느 모듈이 어느 핀인지 모른다.** 알 필요가 없다 — 서버는 *이름* 으로 부르고,
그 이름에 붙은 함수가 핀을 안다. **그래서 핀이 둘인 센서도 특별한 것이 없다.**

⚠ 극성(`HIGH`/`LOW`)·문턱·필터는 **센서마다 다르다.** 프레임워크에 기본값을 두면
절반은 틀리므로 두지 않았다. **틀린 기본값보다 없는 것이 낫다.**

## 5. 링크 계층 — 고쳐도 된다. 다만 비용이 있다

🔒 표시된 헤더들(`RxBuf`·`RxLine`·`LinkGate`·`LinkRecovery`·`EspLink_*`)은
**링크 안정성이 걸린 코드**다. ESP 가 꼬였을 때 **자력으로 돌아오는 경로**가 여기서 나온다 —
이 코드가 도는 덕분에 **하드웨어 리셋선이 필요 없다.**

**금지가 아니다.** 다만 고치면 **안정성 기준선을 다시 재야 한다.** 기준선은 이렇게 생겼다:

```
무자극 41분 동안  CIFSR 0.0.0.0 0회 · LADDER 실패 0회 · T2 0회 · esprst 0회 · 깨진 나가는 AT 0건
```

🔑 **"만지지 마라"가 아니라 "만지면 그 비용을 안다"이다.** 고쳤으면 **알려라.**

### `#include` 순서

스케치는 전처리된 하나의 파일로 컴파일된다. **순서를 바꾸면 선언·초기화 순서가 같이
바뀌고 산출물이 달라진다.** 새 헤더는 **목록 끝**에 더한다.

## 6. 진단 줄 읽는 법

| 줄 | 언제 나오나 |
|---|---|
| `[PARKING NODE] N spots / M sensors / K modules` | 부팅 1회. 🔴 **셋은 다른 값이다** |
| `[REG] 등록 전송 <크기>B` | 등록할 때. 크기 = `10 + 11×모듈수` |
| `[G] idx=n arg=v` | 명령이 콜백에 닿았다 |
| `[G] 거절 idx=n — <사유>` | 위 셋 중 하나 |
| `[DIAG] offline …` | 오프라인 3초마다 |
| `[CNT] …` | 운영 계수기 |

⚠ **같은 `rid` 를 다시 받으면 `[G]` 줄이 안 나온다**(멱등 — 캐시된 ACK 만 다시 보낸다).
**서버가 재전송하면 장치는 조용하고 ACK 만 간다. 그 침묵은 정상이다.**
