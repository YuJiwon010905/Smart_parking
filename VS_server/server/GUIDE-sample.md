> **`lot.cpp` 는 따라 치는 파일이고 이 문서는 읽는 파일이다.**
> 🔴 **거기에 `main()` 은 없다** — 여닫고 도는 순서는 기여자가 못 바꾸므로 엔진(`entry.h`)이 갖는다.
> 코드에는 *"여기서 무엇을 하는가"* 와 **모르면 바로 틀리는 함정**만 두고,
> *"왜 그런가"* 는 전부 여기 있다.

작성: socket-engineer · 2026-08-19 · **조립 API v2 반영 2026-08-20**

> 🔑 **따라 칠 코드는 같은 폴더 `EXAMPLES.cpp` 에 있다** — 개념 하나에 함수 하나이고
> **컴파일된다.** 이 문서는 *왜 그런가* 를 읽는 곳이고, 거기는 *무엇을 치는가* 를 베끼는 곳이다.
> ⚠ 주석 안의 예시는 아무 검사도 안 받아 조용히 낡는다. 그래서 예제를 컴파일되는 자리로 옮겼다.

> ⚠ **v1(`sensor()`/`actuator()`/`gate()`)로 적힌 옛 예시를 보고 있다면 그것은 낡았다.**
> 지금 그 이름들은 **없다.** 컴파일이 막는다.

## §조립 — 자리에 모듈을 붙인다

### 🔑 배우는 것은 **다섯**이다 — `spot` · `at` · `parking` · `label` · `module`

```cpp
lot.spot("A1")                       // 자리 하나
    .at(0, 0)                        // 화면 격자 위치(행,열)
    .parking()                       // 🔴 주차영역 — 점유·예약이 뜻이 있다
    .label("1번 자리")                //    화면에 보일 이름
    .module("P1", "A1")              // 모듈을 붙인다
    .module("P1", "B1")
    .module("P1", "LD");

lot.spot("E1").at(0, 2).label("입구");                       // 일반영역(기본값) · 모듈 없음
```

### 🔴 `parking()` 이 **유일하게 엔진 동작을 바꾼다**
```
① 점유 계산에 든다   ② 예약 대상이다   ③ 옛 격자(폴백)에 든다
그 밖에는 엔진이 자리가 무엇인지 몰라도 된다
```
⚠ **기본값은 "일반영역"이다.** `parking()` 을 **적어야** 주차 자리가 된다.
🔑 **왜 그 방향인가**: 안 적었을 때 점유·예약이 **안 생기는 쪽**이 조용히 틀리지 않는다.
반대로 두면 입구가 *"비어 있는 주차 자리"* 로 화면에 뜬다.
> **틀렸을 때 조용한 쪽을 기본값으로 두지 마라.**

### `at(행, 열)` — **사용자 인식용. 엔진은 안 쓴다**
- 0-기준 **격자** 좌표다. 자유 좌표가 아니다.
- **안 적으면 선언 순서대로 자동 배치**된다.
- 격자 크기는 서버가 계산한다 — `rows = max(행)+1` · `cols = max(열)+1`.
- ⚠ **같은 칸에 둘을 놓으면 화면에서 하나가 가려진다.** 기동 로그가 **두 자리 id 를 지목해** 말한다.
  막지는 않는다 — 표시 문제이고 서버 동작은 멀쩡하다.

### `label(...)` — 화면에 보일 이름
안 쓰면 자리 id 가 뜬다. **모듈에도 붙는다**: `lot.label("P1", "A1", "왼쪽 센서")`.
🔑 이름의 정본은 **이 한 곳**이다. 두 군데서 이름을 주면 우선순위 규칙이 생기고, 규칙이 생기면 사람이 틀린다.

### 🔴 `sensor()` / `actuator()` 가 **없다** — `module()` 하나다
```
장치가 등록(`D`)에서 `kind` 첫 글자로 이미 말한다 :  `I` = 관측(센서)  ·  `O` = 명령
서버가 그것을 보고 가른다. **조립 표에서 또 가를 이유가 없다**
```
- **점유 판정에는 `I` 로 시작하는 모듈만 든다.** 차단봉이 열렸다고 그 자리에 차가 있는 것이 아니다.
  🔑 v1 에서는 기여자가 `actuator()` 로 갈라 줘야 했다. 지금은 **장치가 말하므로 틀릴 자리가 없다.**
- 🔴 **딸린 결과 — 등록 전에는 무엇이 센서인지 모른다.**
  ```
  등록 전 :  value_state:"unknown" · value_known:0 · value_total:0
  ```
  **`0` 은 "센서 없음"이 아니라 "아직 모름"이다.** 화면도 그렇게 그린다.
  🔑 선언만 보고 센서 수를 세면 장치가 다른 것을 보고해도 안 바뀐다 — 그건 *아는 척*이다.

### 🔴 모듈 이름은 **정확히 2바이트 ASCII**

장치의 모듈 표가 `char name[3]`(2글자 + NUL)이고 **전선에도 그대로 나간다.**
```
장치 : 3글자 이상을 적으면 **컴파일이 막는다**
서버 : **안 막는다** → `"LED1"` 이라고 적으면 그 모듈은 **영영 안 붙는다**
```
🔴 **막는 방식이 양쪽에서 다른 것이 함정이다.** 서버는 기동 로그에 **이름을 지목해** 말한다 —
증상이 `미결속모듈` 뿐이면 *"안 쓰기로 한 것"* 과 구분이 안 되기 때문이다.
⚠ 한글은 한 글자가 3바이트라 쓸 수 없다.

### 이름이 자리 id 와 같을 필요는 없다
`module("P1","Q7")` 도 붙는다. 전에는 *"모듈 이름 = 자리 id"* 라는 **암묵 규칙**이 있었고,
`devid` 를 받게 되면서 사라졌다.
🔑 같은 이름을 **두 자리에** 적으면 앞엣 자리가 이기고 뒤엣 자리는 그 모듈을 영영 못 받는다 —
서버가 그것도 지목해 말한다.

### 선언하지 않은 모듈은 **꺼진 것**이다
장치에 있어도 화면에 안 나온다. 서버는 그것을 `미결속모듈 N/M` 으로 센다.
```
· 내가 **켠 자리에 붙어야 할** 모듈이 거기 뜨면  → 🔴 **실수다**
· 내가 **안 켠 자리의** 모듈이 뜨면              → ✅ **정상이다**
```
⚠ **수를 보고 놀라지 말고 *어느 모듈인지* 를 봐라.**

### `devid` — 장치의 `#define DEVICE_ID` (1~8자)
🔴 기본값 `"P1"` 을 안 바꾸면 **모두가 같은 id** 가 된다.
**혼자 시험할 때는 멀쩡하다가 합치는 순간 서로 쫓아낸다.** 서버가 기동 때 `예시devid` 로 말해 준다.
🔑 장치가 하나뿐이면 `module("A3")` 처럼 **devid 를 빼도 된다** — *"아무 장치나 그 이름을 가진 것"*.

## §조작 — 화면에서 모듈을 직접 움직인다

**뜻을 아는 사람이 선언한다.** 화면은 **입력 형태**만 알고 **뜻은 라벨로만** 받는다.

```cpp
lot.control("P1", "LD").toggle();                    // 0 / 1
lot.control("P1", "L2").number(0, 9999999);          // 숫자 입력 칸
// ⚠ 아래 `choice` 는 **가상의 예**다 — 지금 이 샘플의 장치에는 그런 모듈이 없다.
//   (차단봉을 없앴다 · 2026-08-20) **API 는 그대로 있으니 네 모듈에 쓰면 된다.**
lot.control("KIM01", "DR").choice()                  // 🔑 이 선언이 곧 명령표다
      .option(1, "열기").option(2, "닫기");
```
```
위젯은 셋뿐이다 : toggle · number · choice   ⚠ 늘리지 마라
넷째를 만들고 싶어지면 대개 **뜻**을 화면에 넣으려는 것이다 — 그건 라벨의 일이다
```
- **선언 안 한 모듈은 화면에 조작 UI 가 없다** (`module()` 의 *"선언 안 한 것은 꺼진 것"* 과 같은 규칙).
- 🔴 **범위 판정은 서버가 한다.** 화면이 먼저 막아도 좋지만 서버는 믿지 않는다 —
  벗어나면 `out_of_range` 로 거절한다.
- ⚠ **에코는 비트 하나다.** `1234567` 을 보내도 되돌아오는 것은 *"0이 아니다"* 뿐이라
  화면의 `confirmed` 는 **`partial`** 까지만 참이다. **숫자 값 확인은 지금 안 된다.**

## §명령 — `srv.send(devid, 모듈이름, 값)`

```cpp
srv.send("P1", "LD", 1);          // on/off       ← 이 샘플에 있는 모듈
srv.send("P1", "L2", 1234567);    // 7자리 숫자     ← 이 샘플에 있는 모듈
srv.send("KIM01", "DR", 2);       // 동작           ⚠ **가상** — 네 모듈로 바꿔 읽어라
```
셋이 **같은 함수 하나**다. 다른 것은 **값의 뜻**뿐이다.

### 🔴 명령 작성 방법 — 이 절이 핵심이다

**값의 뜻을 서버도 프로토콜도 모른다.** 그냥 32비트 정수를 실어 나른다.
뜻을 정하는 것은 **기여자**이고, 정한 표를 **양쪽에 똑같이** 적어야 한다.

```
여기(서버 호출부)  ─── 같은 표 ───  장치의 콜백(client.ino)
```

⚠ **표가 어긋나면 조용히 다른 동작을 한다.** 오류도 안 뜬다 —
**서버는 `2` 를 보냈고 장치는 `2` 를 받았으니 양쪽 다 성공이다.**
> ### **의미는 값으로 검증되지 않는다. 사람이 맞추는 수밖에 없다.**

🔑 **`choice` 로 선언하면 그 표가 화면에도 그려지고 한 곳이 된다.** 위 §조작을 먼저 봐라.

❌ 표 없이 `1,2,3,4` 만 쓰지 마라. ✅ 이렇게 적는다:
```cpp
// [DR 명령표]  ⚠ **가상의 예다** (모듈 "DR" · 정한 사람: 홍길동) — 이 샘플에는 없는 모듈이다
//   1 = 열기   2 = 닫기   3 = 잠금   4 = 잠금해제
//   ⚠ 그 외 값은 장치가 result=3(수행 불가)로 답한다
srv.send("KIM01", "DR", 1);
```
장치 쪽(`client.ino`) — **같은 표를 그 위에 복사해 둔다:**
```cpp
// [DR 명령표]  1=열기 2=닫기 3=잠금 4=잠금해제   ← 위와 똑같이
bool cmdDoor(uint32_t arg) {
    if (arg == 1) { /* 열기 */ return true; }
    return false;            // 🔑 모르는 값은 false — 조용히 성공하지 마라
}
router.on("DR", cmdDoor);    // setup() 에서 등록한다
```
🔑 **값 검사는 라우터가 아니라 *기여자의 콜백* 이 한다.** 라우터는 값의 뜻을 모른다.

### 🔴 `send()` 의 `true` 는 "보냈다"이지 "됐다"가 아니다
**큐에 넣었다**까지만 말한다. 결과는 §콜백이 나른다.
⚠ **조립 시점에 부르면 실패한다** — 장치가 아직 안 붙어 있다.
그래서 명령은 `onTick(ParkingServer&)` 안에서 낸다. `srv.deviceReady("P1")` 로 먼저 확인해라.
🔑 주기 동작이 필요하면 `srv.nowMs()` — **단조 시계(ms)**. 벽시계가 아니다.

## §콜백 — 결과를 나중에 받는다

```cpp
void onCmdResult(const CmdResult& r) { /* r.module · r.value · r.kindName() */ }
```

### 🔴 갈래가 셋이고 **고치는 곳이 다르다**
```
성공(OK)         장치가 받았고 콜백이 true 를 냈다
거절(REJECTED)   장치가 **답했고** 거절했다 → 값·등록을 고쳐라. **재시도는 뜻이 없다**
무응답(NO_ANSWER) 🔴 **답이 없다**(재전송 소진) → 장치·링크 문제다.
                  **콜백 로직을 고쳐도 안 낫는다**
```
🔑 **뭉치면 기여자가 장치 고장을 자기 콜백 로직으로 쫓는다.**

### ⚠ `result=0` 은 물리적 성공이 아니다
*"콜백이 `true` 를 냈다"* 는 뜻이다. **차단봉이 걸려도 `true` 가 온다.**
그것까지 알려면 **장치가 읽어서 보고하는 값**이 필요하고, 지금은 그 계약이 없다.

### 콜백을 비워 둬도 관측은 남는다
**계수기는 그대로 센다** (요약 줄 `명령결과 성공 N/거절 N/무응답 N`).
🔑 **볼 자리를 선택적인 것에 묶지 않았다** — 묶었으면 콜백을 안 쓰는 동안 관측이 통째로 비었다.

## §묶음 — 한 창에 같이 나가는 것이 **보장된다**

```cpp
ParkingServer::Batch b = srv.batch("P1");
b.add("LD",1).add("L2",7654321);          // ⚠ 있는 모듈만 적어라 — 없는 이름은 거절된다
ParkingServer::BatchResult r = b.send();
```

### 왜 묶나
하행은 **슬롯당 한 창**(1.2초)에만 나간다. 낱개 N건이면 **N × 1.2초**.
묶으면 **하행 1슬롯 + ACK 1슬롯 ≈ 2.4초**로 끝난다.

### 🔴 원자성이 **두 층**이다 — 섞으면 못 지킬 약속이 된다
```
✅ **창 원자성**  : 전부 **같은 창**에 나가거나 **한 건도 안 나간다**  → **보장한다**
❌ **실행 원자성** : 전부 성공하거나 전무                              → **보장 안 한다**
```
**되돌릴 수단이 없다.** 전선에 나간 뒤에 취소할 방법이 없고, *"전부 성공했을 때만 적용"* 을
하려면 장치가 2단계 커밋을 해야 한다.
> ### **못 지키는 보장을 API 가 약속하면, 그것을 믿고 쓴 코드가 조용히 틀린다.**

### 🔴 상한을 넘기면 **거절한다. 자동 분할 안 한다**
쪼개면 두 창에 걸쳐 나가고 **묶은 뜻이 사라진다.** 거절이 정직하다.
```
상한은 상수가 아니다 — `srv.maxPerBatch()` 가 그 순간 값을 준다(지금 4)
기동 로그의 `묶음 상한 N건` 이 같은 값이다
🔑 유래 : 장치의 **ACK 배출률**에서 유도된다. 올리려면 장치 쪽 수가 먼저 바뀐다
```

### ⚠ 묶음은 손실 **크기**를 키운다
서버 송신이 장치 송신과 겹치면 지금은 **한 줄** 손실인데, 묶으면 **N−1 줄**이 사라진다.
**확률은 그대로고 크기만 N배다.** 그래서 **수신 창 안에서만** 보낸다.
🔑 실기 확인: `+IPD` 헤더 **1건**에 `G,` 넷 — 연발이 아니라 진짜 한 조각으로 도착했다.

## §심화 — 자리 판정을 직접 쓰기 (안 써도 된다)

**기본 판정으로 충분하면 건너뛰어라.** `spot(...).parking().module(...)` 만으로 자리는 정상 동작한다.

기본은 **OR** — 아는 센서 중 하나라도 찼으면 찼다.
🔑 두 오류의 대가가 다르기 때문이다: 빈 자리를 "찼다"고 하면 손해는 자리 하나이고,
**찬 자리를 "비었다"고 하면 운전자가 가서 못 댄다.**

```cpp
struct 둘다찰때만 : SpotBehavior {
    virtual bool occupied(const std::vector<SensorReading>& s) const {
        int k = 0, v = 0;
        for (size_t i = 0; i < s.size(); i++)
            if (s[i].known) { k++; if (s[i].value) v++; }   // 모르는 센서는 안 센다
        return k > 0 && v == k;
    }
};
static 둘다찰때만 g_내판정;    // 🔴 서버보다 오래 살아야 한다(static/전역)

lot.spot("A1").parking().module("P1","A1").module("P1","B1").behavior(g_내판정);
```
⚠ `SensorReading` 은 `known` 과 `value` 가 **따로다.** `known == false` 는
*"아직 값을 못 받았다"* 이지 *"비었다"* 가 아니다.
🔴 **둘을 한 `bool` 로 합치면 모름이 거짓으로 무너진다.**
🔑 여기 오는 것은 **`I` 로 시작하는 모듈뿐**이다 — 명령 모듈은 애초에 안 섞인다.

## §에코 — 장치가 되돌려 주는 값

명령을 보내면 다음 상태 프레임의 그 모듈 `value` 가 바뀐다.
```
LD 1(켜기) → value:true      LD 0(끄기) → value:false
```
🔑 **계약은 `arg` 를 그대로 싣는 것**이지 `0/1` 로 접는 것이 아니다.
전에 `arg != 0` 으로 접던 시절, 값 `2`(끄기로 정한 기여자의 표)가 **켜짐으로 남아**
*"껐는데 서버는 켜진 줄 안다"* 가 됐다. **그래서 지금은 값을 그대로 보낸다.**

### 🔴 에코가 답하지 않는 것
```
`에코 == 요청` 은 **"장치가 그 값을 갖고 있다"** 이지 **"명령이 상태를 바꿨다"가 아니다**
차단봉이 걸려도 에코는 선다 — 물리적 확인은 **읽는 센서**가 있어야 한다(지금 없다)
⚠ 에코는 **비트 하나**라 `LC`·`L2` 는 **"0이 아니다"만** 말한다. `1234567` 은 안 돌아온다
```
